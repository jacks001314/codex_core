## codex_core Adaptations

- Rewrote internal imports from `codex_go/...` to `codex_core/...` across 562 Go
  files.
- Changed the Code Mode protobuf `go_package` to
  `codex_core/codemode/grpc/codemodev1` and regenerated the Go protobuf files.
  Regeneration was required because changing the raw descriptor string without
  updating its length prefixes caused a protobuf init panic.
- Updated `go.mod` from the source dependency graph, changed the module name to
  `codex_core`, and ran `go mod tidy`. TUI-only dependencies remain excluded.
- Adapted the copied TUI/host file scan test to skip source read sites that do
  not exist in this embeddable module while still validating the accepted
  strict-config key set.
- Adapted the Plan preset parity test to skip when the intentionally excluded
  TUI client file is absent. The embedded Plan preset itself is still tested.
- Preserved applicable pre-existing formatting-only edits in 16 synchronized
  files. The one `plugin-creator` file that could not be restored was removed
  by the upstream source tree.

## Verification

All checks completed successfully on Windows/amd64 with Go 1.26.5:

```powershell
go mod tidy
go list -buildvcs=false ./...
go build ./...
go vet ./...
go test -p 1 ./... -count=1
go build ./examples/...
go run ./examples/event_sink
$env:GOOS='linux'; $env:GOARCH='amd64'; $env:CGO_ENABLED='0'; go build ./...
git diff --check
```

The full test suite was serialized to avoid contention among the heavier
`model`, `state`, and `tool` packages. An initial full run exposed the protobuf
descriptor problem and two removed-UI path assertions; after the adaptations
above, the complete serialized suite passed.
